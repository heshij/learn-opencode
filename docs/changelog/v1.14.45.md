# v1.14.45：Provider 与旧会话兼容性修复

**发布日期**：2026 年 5 月 10 日

## 一句话总结

Provider API 接受 `active` 模型，并修复权限路径、workspace API 和旧会话加载问题。

## 新功能或行为变化

- Provider 配置与 API 响应现在接受标记为 `active` 的模型。
- `throwOnError: true` 会抛出包含 Server 消息的真实 `Error`，响应正文保存在 `cause` 中。
- 使用已弃用 `api.command` 的 TUI 插件暂时仍可工作，以便迁移到 `api.keymap`。

## 问题修复

- 修复 read 工具权限规则未按 worktree 相对路径匹配的问题。
- 修复 workspace 路由 API 拒绝有效 `directory`、`workspace` 查询参数的问题。
- 修复启动只报告首个 bootstrap 错误、消息请求失败导致会话崩溃的问题。
- 恢复缺少 diff 文件详情或 patch 的旧迁移会话，并隔离 Provider 插件对共享模型状态的修改。

## 影响范围

影响 Provider、权限配置、workspace HTTP API、TUI 插件和旧会话用户。

## 是否需要升级

使用上述能力或无法打开旧会话时建议升级；插件作者应开始迁移已弃用 API。

## 升级命令

```bash
opencode upgrade
```
